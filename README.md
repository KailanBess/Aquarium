# Aquarium

Aquarium is a native .NET 10 LTS / WinUI 3 Windows hub for FishTank (security), FishBowl (gaming) and FishNet (media). Version **0.13.0** adds the independent [Text Editor](docs/TEXT-EDITOR.md) with tabs, strict text encodings, explicit conflict-aware saves, a separate lexical syntax preview and Windows user-scoped encrypted recovery. It includes pinned FishTank 0.19 dependency advisory review and FishNet 0.6.4 local activity review in its offline bundle. It retains Aquarium local activity review using Core 0.4, the independent System Center and System Monitor, portable diagnostics, explicit support export and encrypted photo/PDF record backup. Path-only export dialogs preserve prior destinations until validation and atomic publication. Managed cleanup/uninstall refuses custom FishNet profile selectors so their data can be preserved first.

The broader roadmap comes from the [shared ecosystem specification](https://chatgpt.com/share/6b08a8dd-e4a8-83e9-ab79-0f2360b34a3e) and its supplied full text. The versioned requirements tracker records implemented work separately from the remaining overhaul. Tailscale and private networking are excluded.

## Install and launch

Download `Aquarium-complete-windows-x64.zip` from [Releases](../../releases), extract its single `Aquarium.exe`, and run it. The launcher verifies and caches the full runtime under `%LOCALAPPDATA%\Aquarium\Runtime`. Preparation appears for a new runtime or a damaged cache, and is skipped for a verified cached launch. Settings and managed apps are stored separately.

The complete bundle includes FishTank and FishNet built from immutable source revisions recorded in `BUILD-INFO.json`. FishBowl is optional under **App install**. Included apps are registered after package verification and never started automatically. No games, firmware, keys or emulators are bundled.

**App install** reads only the approved public releases of `KailanBess/FishTank`, `FishNet` and `FishBowl`. Review each package before installing. Downloads shows progress, cancellation and results. Library launches standalone apps. Uninstall removes managed program folders after the app closes and keeps its profile; an explicitly removed bundled app stays removed.

## Updates and recovery

**Offline packages:** after checking published apps, choose **Save offline package** to download and checksum-verify a companion release into one `.aqpkg` file without installing it. On another PC, use **App install → Install an offline package** and review the app, version, size and checksum before installation. No network is needed for this import. Version pins remain enforced, previous program versions and profiles are kept, and nothing launches automatically. The package contains program files and metadata, not app profiles or media. Its included checksum detects inconsistency; it does not independently authenticate its publisher. Use a package saved from a trusted release. Canceled or invalid imports do not register an installation.

**Update all apps** checks Aquarium and installed companions using saved release channels, skips pinned/current/older versions, presents one review, verifies each package and continues after an individual failure. Cancel stops remaining work. Aquarium stages itself last and asks you to reopen it. Optional interactive WinGet updates cover only outside apps WinGet can identify; recheck after their installers finish.

**Recovery** exposes package verification/repair and retained-version rollback. Close a companion before rollback. Older versions may interpret newer profile data differently. **Review unused program folders** offers only unregistered GUID version folders and preserves all current and retained rollback versions. Linked paths and portable FishBowl data block cleanup. Reviewed cleanup also offers older named runtime caches, keeps the active/current version and newest previous cache, and requires exclusive access to every candidate file before deletion. Older launchers can prepare a removed cache again. Preparing/damaged or unrecognized folders are left alone.

**Encrypted app records** lets you choose profiles and a passphrase of at least 12 characters. Backups use authenticated AES-256-GCM encryption with PBKDF2-SHA256 (600,000 iterations). Restore previews the apps/file count, preserves an encrypted before-restore backup beside the selected archive, and rolls back completed record writes if a later write fails. A running FishBowl/FishNet profile lease blocks conflicting recovery in supporting versions. Close selected companions first.

Backups include Aquarium settings/registry, FishBowl library records, FishNet catalog/playlists/queue/preferences/podcast subscriptions/radio stations/playback positions, and Device Inventory/Workspace Launcher records. **They do not copy referenced games, saves, media, artwork, receipt files, downloaded podcasts, portable profiles or programs. FishTank includes appearance only.** Use FishBowl's save backups and FishTank's authenticated encrypted backup/restore tools for those data. Paths may need repair on another computer; Windows-account-protected credentials may need reenrollment. The record limit is 64 MB. Keep the passphrase separately; there is no passphrase recovery service.

**Preview support report** shows exactly the versions, platform, registry state and counts to be saved. It excludes paths, library contents, credentials and raw logs. Nothing is sent automatically.

## Appearance and navigation

Settings previews Aquarium colors, corners, spacing, headings, sidebar and frame. Apply saves; leaving Settings discards unapplied previews. **Apply a family palette** reviews Ocean/Midnight/Slate with Mint/Blue/Coral for initialized, closed companion profiles. It preserves unrelated settings and future JSON fields, disables custom palettes while retaining their stored colors, and keeps `.family-before.bak` records beside changed files. Each app can still be customized independently afterward.

**Shared quiet hours** is optional. Supporting FishBowl versions defer informational release/save-review balloons while retaining review items. FishTank release announcements honor the policy; security warnings and errors retain their own controls. Aquarium, FishNet and the smaller tools do not currently emit background desktop notices. Equal start/end hours leave notices enabled all day.

The shared search finds Aquarium pages and companion apps by name/category/description. It opens the relevant hub page; companion tools remain available inside their own app.

## Standalone tools

Optional **App install** entries and separate release ZIPs provide **File Organizer**, **Device Inventory**, **Workspace Launcher**, **System Monitor** and **System Center**. Managed copies participate in Library, repair, rollback and Update all apps. Their managed package versions follow Aquarium suite release tags; the tool executable version is independent. Extract each complete ZIP before running its executable. They use the family palette and Windows High Contrast on startup.

- File Organizer previews rename/move operations, refuses overwrites/linked paths, compares duplicates without deleting them, keeps in-session undo and persistent source/destination recovery records. Recovery records are not file-content backups. Moves run without freezing the UI, and closing waits for an active move.
- Device Inventory records devices, serials, receipt links, warranty and maintenance dates. Receipt files stay external.
- Workspace Launcher records selected desktop executable windows and reviews their paths before launching/positioning them. Missing or inaccessible apps are reported individually. It never stores arbitrary command lines.

- System Monitor shows read-only Windows CPU, physical-memory and process working-set observations every two seconds while open. It supports pause/resume, process-name filtering and sorting. History retains at most 900 CPU/physical-memory/process-count entries in memory (roughly 30 minutes at two-second sampling; pause/resume and failed collections also use entries). Older entries are dropped with an explicit count. The separate history window shows UTC timestamps and collection sequence, so clock changes do not reorder observations. Pause/resume and unavailable markers never infer zero CPU or uninterrupted coverage. History stores no process names or IDs, is discarded when System Monitor closes and is written only by an explicit JSON export. Snapshot export still includes process names/IDs and retains its separate warning. A delayed capture cannot cross a pause/resume boundary. First/new/reused/missing CPU samples stay unknown. System CPU covers the primary Windows processor group; process CPU is normalized to the machine logical-processor count. Process working sets share memory and cannot be summed to unique RAM usage. Explicit JSON export reviews the destination and explains that process names/IDs are included. Nothing uploads automatically. GPU, disk/network rates, temperature, power consumption, process termination and Linux UI support remain future work. See Microsoft's [system timing](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes) and [physical memory](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex) API coverage.

## Integrity and signing

Packages require GitHub asset digests or matching SHA256SUMS entries, bounded extraction and contained executable paths. Traversal, duplicate paths, symlinks and oversized packages are rejected. Registry saves are atomic; unreadable registries are preserved with edits disabled. A process-lifetime profile lease prevents simultaneous Aquarium writers.

Release packaging can sign and verify Aquarium's runtime/launcher and standalone tools using genuine publisher credentials. Configure repository secrets `WINDOWS_SIGNING_PFX_BASE64` and `WINDOWS_SIGNING_PASSWORD`, and variable `WINDOWS_TIMESTAMP_URL` with the provider's HTTPS RFC 3161 endpoint. Only main/tag release packaging receives those credentials. Missing configuration yields an explicitly unsigned package; partial configuration or failed signature/timestamp verification stops packaging. `BUILD-INFO.json` records the actual hub signature state. No signing credentials are included in source or releases. Companion signature states are independent.

Checksums verify consistency with trusted repository metadata; they are not independent publisher authentication. Windows builds remain unsigned until genuine signing configuration is supplied. Signing is not a security audit.

## Build and verification

The first shared infrastructure lives in `src/Aquarium.Core`. This portable .NET 10 library has no WinUI, running-hub or account dependency. Aquarium uses its atomic registry writes, exclusive profile leases and path checks. Consumers still own their schemas and hold the profile lease while writing; path checks are not an OS sandbox or protection against a malicious process racing filesystem operations. Same-directory rename avoids partial records, but is not a guarantee against every filesystem or power failure. Run `dotnet run --project tests/Aquarium.CoreTests -c Release`; CI checks Windows and Linux. Legacy .NET Framework apps need a compatible adapter before adopting this library.

The broader work is tracked in `docs/overhaul-requirements.json`. A `needs-audit` status does not mean the capability is absent. Tailscale and private networking are excluded. This branch implements the initial Core infrastructure and offline packages; it does not complete the entire ecosystem overhaul.

Core also provides `JsonSettingsStore<T>` for bounded, versioned JSON settings. Explicit migrations run in memory; only a requested save publishes them. Unknown object properties survive ordinary saves. Unsupported newer schemas, duplicate JSON keys and invalid settings are preserved and refused. Revision checks and an exclusive record-writer lock reject stale or conflicting saves. Optional `.previous` records support validated restoration. Aquarium appearance uses this SDK for Apply and Undo, retaining existing flat JSON settings and custom colors. A failed or canceled write retains the active record. Other settings files have not all migrated to this SDK yet; cooperating callers must use its writer protocol, and it is not an OS sandbox.

The next Core diagnostics API uses versioned reports and read-only `IDiagnosticProbe` providers. Reports distinguish Available, Warning, Unavailable, Unsupported and Unknown observations. Probe failures use fixed codes instead of raw exception text. Collection runs off the caller's UI thread, limits the number of probes and bounds each wait; providers must still honor cancellation because timed-out code cannot be forcibly stopped. Identifiers and codes are developer-owned labels and must not contain private values. Completion timestamps do not certify sensor freshness or authenticate providers. Nothing is uploaded automatically.

Aquarium's support-report preview includes these observations for loaded registry state, active package operations and recorded checksum metadata. An empty/unreadable registry gives unknown package coverage. A recorded hash is explicitly not a fresh file verification or publisher-trust finding. Existing top-level support fields remain; unrecognized version text is redacted rather than copied into the export. Logging, operating-system health probes and the complete diagnostics framework remain separate work.

Requires Windows 10 build 19041+ x64 and the .NET 10 LTS SDK. The complete bundle is self-contained; Visual Studio is optional.

```powershell
dotnet build src/Aquarium/Aquarium.csproj -c Release -p:Platform=x64
dotnet run --project tests/Aquarium.PackageTests -c Release
dotnet run --project tests/Aquarium.LauncherTests -c Release
```

CI builds the complete runtime and tools, tests package/registry integrity, encrypted backups and restore failure, profile leases, family-palette preservation, quiet hours and launcher startup. Publication from reviewed main source or a matching tag requires passing packaging checks and creates a versioned release. A source commit alone is not an installable update. Physical display/screen-reader acceptance, live companion interaction and interruption testing remain manual checks. No private VPN, network-management or iOS integration is included.

System Center provides local OS/runtime/architecture, logical-processor and Windows physical-memory observations plus a filterable snapshot of account-visible user-mode service states. Refresh is manual; export is explicit, reviews OS/service-name contents and uses atomic publication. It does not query host/user names, service accounts or command lines; process IDs returned by the native enumeration are discarded before presentation/export. Missing permissions are unavailable, native malformed data is unknown, unsupported platforms are explicit, and buffer/count limits remain visible. Service enumeration may omit inaccessible services, and drivers are excluded. State is not a health/protection verdict; no settings or services are changed. Hardware identity/driver management, storage inventory, repair and Linux UI remain open. Native service access uses [enumeration rights](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights) and follows Microsoft's [enumeration coverage and buffer limits](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-enumservicesstatusexw).

Settings → Local activity history reviews up to 500 app-start and notice-severity records, timestamps and app versions. Raw notice/error text, paths, library records, credentials and stacks are not captured. An explicit reviewed JSON export omits unknown additional fields and refuses the profile/program folders. Existing histories are preserved when unreadable or unsupported; write failures leave other features available and may mean some events are missing. This is local operational history, not cross-app adoption, crash collection or desktop-notification history; the default support report and record backup exclude it.
